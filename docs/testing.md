# 验证方法

这些检查用于区分“文件结构可读”和“恢复结果正确”。生成 CMO3、编辑器能打开文件，都不能单独证明恢复成功。

## 工具和样本

构建工具见 README。输入检查使用 `recovery-cli`；运行时对照可使用自行安装的官方 Cubism Core SDK；工程验证使用自行安装的 Cubism Editor。Python 标准库足够制作 JSON 变体、检查 ZIP/XML 内容和比较结果。官方组件仅用于本地验证，不链接进转换程序，也不随源码分发。

使用自己创建或明确获准用于测试的小模型。建议包含一个三角形网格、一个遮罩、普通参数、叠加参数、父子变形器及部件。另建简单贴图和物理配置，以便定位单个功能。更复杂的私有模型可用于本地回归，不能提交它的模型、贴图、名称、ID、路径、日志或恢复结果。公开问题报告只保留匿名统计和最小复现步骤。

## 输入检查

每次只修改输入副本中的一个字段，保留原始文件。对每个变体运行：

```powershell
.\recovery-cli.exe --inspect .\fixtures\example.model3.json
```

| 检查 | 预期行为 |
| --- | --- |
| 截断 MOC、错误签名、未支持的格式或字节序 | 返回明确错误，不崩溃 |
| 超出文件的数据段、负数计数、超大关键形组合 | 拒绝读取，不分配无界内存 |
| 越界父级、父级循环、无效三角形或遮罩索引 | 拒绝读取 |
| 非有限浮点数、重复参数 ID、未严格递增的参数键 | 拒绝读取 |
| 未知网格绘制标志位 | 拒绝读取，不悄悄忽略该标志 |
| Groups 引用未知参数、重复参数或非 Parameter 目标 | 拒绝读取 |
| 正确的 EyeBlink、LipSync 组 | 保留名称和参数引用 |
| 未支持的效果组、UserData、MotionSync | `canExport` 为 false，原因列于 `unsupported` |
| 物理配置或显示分组包含不支持、无效的结构 | 检查阶段就报告，阻止导出 |
| Motions、Expressions、Pose 引用 | 明确说明这些独立资源不转换进 CMO3 |

`--inspect` 成功只表示完成检查。必须同时检查 `canExport` 和 `unsupported`；未支持项不能被误判成“恢复完成”。转换到已有目标文件时必须拒绝覆盖，失败后原输入与原目标的内容应保持不变。

## 数值和工程对照

用官方 Core 对同一个 MOC 求值，比较参数范围、默认值、循环标志、网格顶点数量、UV、三角形、遮罩、绘制标志和默认渲染顺序。比较 UV 和三角形前，应按 [格式说明](format-notes.md) 统一坐标与绕序约定。普通关键形组合顺序与叠加中性键需要分别检查。

在 Cubism Editor 中打开新工程，检查默认姿态和各参数的端点、中间值。对普通参数与叠加参数同时变化的情况也要检查；只验证默认姿态无法发现错误的关键形组合。数值比较需覆盖全局顶点、透明度、绘制顺序、颜色、遮罩与父级影响。报告最大误差及容差，不能只报告“打开成功”。物理参数、参数分组和效果组则需在对应编辑器面板核对。

检查生成 XML 时，每个共享对象的 `xs.id` 只能完整定义一次，其余位置必须使用 `xs.ref`。用编辑器对象 API 做本地诊断时，还应验证网格、表单、参数绑定、纹理输入的 owner/source 引用身份一致；重复对象可能在加载时不报错，却在验证或显示贴图时失败。

最后在编辑器中保存为另一个新文件并重新打开，确认没有新增验证错误。测试记录应明确区分结构检查、数值对照、编辑器显示和保存验证；本说明不是对所有模型兼容性的保证。
