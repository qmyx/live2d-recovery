# 格式与恢复规则

本文记录当前实现采用的结构约束和验证方法。它不是 Live2D 官方格式规范，也不表示所有历史格式或模型特性都已得到验证。项目的实现来源和依赖边界见 [ORIGIN.md](../ORIGIN.md)。

## 旋转变形器的单位

旋转变形器的缩放单位需要结合完整的父级链判断，不能只检查直接父级是曲面还是旋转变形器。

当前已验证的转换规则是：沿父级链向上查找，如果此前没有旋转变形器，则将 MOC 缩放值乘以画布的 `pixelsPerUnit`；如果已经存在旋转祖先，则保持原值。中间经过曲面变形器不会重置这项判断。普通关键形和叠加关键形都必须使用一致的单位换算。

这个规则依据原始 MOC 的层级关系，以及恢复工程和官方运行时计算结果的对照确定。仅凭某个缩放值接近一个常见数值来决定单位，会把模型本身的缩放误认为格式转换。

## 普通关键形与叠加关键形

普通关键形使用参数网格组织。展平网格时，第一个绑定参数变化最快；写入工程时，每个网格关键形仍需明确记录它在各参数上的键值索引。

MOC 中的叠加关键形数据是差值，CMO 中对应的形态则保存完整状态。恢复时先按照各绑定参数的默认值，对普通网格关键形进行插值，得到默认基态，再加上叠加关键形差值。不能简单选择数组里的第一个形态，也不能把差值直接当成完整坐标写入。

这一处理同时适用于位置、角度、缩放、不透明度、绘制顺序和颜色等已支持的数值通道。参数默认值对应的中性叠加形态由基态隐含表示，不额外写成一个叠加目标。叠加约束通过目标参数、控制参数和权重曲线关联到所属对象。

## 相同绘制顺序的先后关系

网格的绘制顺序数值相同时，原始 MOC 中的网格排列仍然决定遮挡先后。当前支持的布局中，按绘制顺序对这个排列进行稳定排序，与官方运行时的渲染顺序一致。

编辑器通过部件树中子对象的反向深度优先遍历确定这些先后关系。因此写入时，需要把直属网格和子部件合并排列，不能先写全部子部件再写网格。子部件采用其全部后代网格在原始排列中的最小位置，与直属网格一起降序写入，反向遍历时就能恢复原始排列。

这要求每个部件的后代网格在原始排列中形成连续区间。当前实现会检查这一条件；无法通过部件树表达的排列会停止导出。验证使用编辑器公开的渲染器排序接口与官方运行时对照，不以对象查询列表的先后代替实际渲染顺序。

## 不支持的数据

解析器只接受明确实现并检查过的文件布局。数据段边界、对象引用、父级循环、关键形组合数量和顶点索引都需要校验；遇到未知或无法可靠表达的结构，应报告原因并停止导出。

显示信息中的参数组合同样需要检查。当前支持已验证的同组、相邻、有顺序的双参数组合，不会把其他组合形式简化为一个标志后继续保存。

## 验证边界

生成文件并不等于恢复正确。验证需要同时检查工程能否被编辑器加载，以及默认姿态的顶点、不透明度、颜色和绘制顺序是否与官方运行时一致。顶点比较应使用有依据的浮点容差，而不是要求多层变形计算的结果逐位相同。

默认姿态验证也不能代替全部参数动作和物理效果检查。MOC 中没有保留的原始 PSD 图层关系和编辑历史，无法通过这些规则重新获得。
